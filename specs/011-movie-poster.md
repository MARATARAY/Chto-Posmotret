# Постер выбранного произведения в форме и каталоге

## Для кого и зачем
Для пользователя «Кадра», который выбирает фильм, сериал или мультфильм из онлайн-подсказок и хочет видеть его постер рядом с данными и в сохранённой коллекции, включая «Избранное».

## Что должно быть
- Использовать результат уже подключённого поискового запроса. Не менять endpoint, параметры, провайдера, заголовок X-API-KEY, ключи, их хранение, задержку 400 мс, локальную конфигурацию и серверный режим. Новых запросов к API за постером или подробностями не добавлять. Загрузка самого изображения браузером через img допустима и не является дополнительным запросом к поисковому API.
- Считать ссылку из выбранного элемента ответа по текущему провайдеру:

| Провайдер | Предпочтительный адрес | Если его нет или он недопустим |
| --- | --- | --- |
| Kinopoisk API Unofficial | item.posterUrlPreview | item.posterUrl |
| ПоискКино | item.poster.previewUrl | item.poster.url |

- Передавать эти сведения через существующие адаптеры movie-api.js и разрешённые поля серверного ответа. Это расширение данных существующего результата, без изменения запроса или способа подключения ключа. Локальный file:// и опубликованный HTTP(S)-сайт используют одинаковое правило выбора URL. Если текущий поисковый ответ не содержит постер, показывать заглушку, не подменять endpoint запросом подробностей.
- Из подходящих полей выбрать первый допустимый непустой URL. Нормализовать его через URL, разрешать только абсолютный HTTPS без логина и пароля. Отклонять javascript:, data:, blob:, file:, HTTP, относительные адреса и повреждённые значения. Не строить адрес по названию, не брать его из пользовательского ввода и не добавлять токен API в URL изображения. Изображение должно загружаться обычным публичным GET без X-API-KEY; если это невозможно — заглушка.
- Хранить нормализованный posterUrl вместе с текущим выбранным произведением в памяти, а не считывать его обратно из img.src. Связь определяется выбранным ID и провайдером. Постеры одноимённых фильмов разных лет, сериалов и мультфильмов не должны смешиваться.
- До явного выбора результата блок предпросмотра скрыт. Сам ввод названия и получение списка не назначают изображение первому результату. После клика, касания или Enter на выбранном варианте рядом с годом, двумя рейтингами и длительностью появляется постер этого произведения. Для каждого варианта в списке отдельные картинки загружать не требуется.
- Предпросмотр имеет устойчивую область с aspect-ratio: 2 / 3, скруглением и тонкой золотой рамкой на бордовом фоне. Использовать object-fit: contain: изображение не растягивается и не обрезается, несовпадающие пропорции компенсируются фоном. Ориентир ширины превью — до 160 px при max-width: 100%; конкретное расположение согласовать с текущей сеткой формы.
- При выборе результата без допустимого URL показать в той же области локальную заглушку «Нет постера» с необязательным символом 🎬. Заглушка создаётся HTML/CSS или существующим локальным ресурсом, не запрашивается у стороннего сервиса. Отсутствие картинки не мешает заполнению остальных данных и не блокирует сохранение.
- Во время загрузки резервировать место 2:3 и сохранять аккуратный фон. При событии error скрыть неуспешный img и показать заглушку без сломанного значка, скачка размеров и циклической смены src. Не повторять загрузку бесконечно и не выполнять дополнительный запрос к API. Адрес можно сохранить даже при временной ошибке картинки, чтобы при следующем открытии браузер мог попробовать загрузить его снова.
- При выборе другого произведения сразу заменить URL и состояние предпросмотра. Старый постер не должен оставаться, пока новый загружается. Привязать load/error к текущему URL и версии выбора: поздняя ошибка картинки A не должна скрывать уже выбранный постер B, а поздняя загрузка A — возвращать его вместо B.
- При изменении названия после выбора снимать привязку к прежнему изображению и скрывать предпросмотр вместе со снятием выбора; личная оценка, статус и заметка сохраняются по текущим правилам. При сбросе и после успешного добавления очищать выбранный posterUrl и состояние ошибки. При отказе localStorage сохранять выбранное произведение и предпросмотр в черновике.
- По кнопке «Добавить в каталог» сохранять в объекте записи posterUrl: проверенную строку либо null при отсутствии постера. Изображение, base64, Blob, canvas и историю загрузок в localStorage не сохранять. Источник и ID использовать уже существующие, без подмены внутреннего ID карточки. Добавление остаётся отдельным действием; выбор постера или его загрузка карточку не создают.
- Если новая запись добавляется без выбранного произведения по действующим правилам формы, её posterUrl равен null, без изображения от ранее выбранного фильма. Эта функция не меняет текущую валидацию названия, года, рейтингов и длительности и не реализует автоматически соседнюю спецификацию readonly-полей.
- В карточках каталога, «Избранного» и «Лучшего» отображать сохранённый постер одной и той же записи в области 2:3 со скруглением, золотой рамкой и object-fit: contain. Заголовок, рейтинги, статус, заметка и кнопки остаются текстом независимо от изображения. Название не заменяется надписью на постере.
- После обновления страницы повторно проверять URL из localStorage перед установкой src и восстанавливать картинку либо заглушку. Избранное не хранит отдельную копию постера: использует исходную карточку по её ID. Удаление с отменой восстанавливает posterUrl вместе с остальными данными; поиск и фильтры не меняют привязку изображения.
- Сохранить ранее предоставленные локальные постеры по specs/009-local-posters.md для старых записей, у которых posterUrl вообще отсутствует. Эти записи и их изображения автоматически не переписывать. Для новой записи с posterUrl-строкой показывать именно сохранённый API-постер; при явном posterUrl=null — заглушку. Не подставлять постер старого одноимённого фильма поверх результата API. Это различие между отсутствующим полем старой записи и явным null новой записи сохраняется после перезагрузки.
- Недопустимый URL или ошибка изображения сохранённой записи дают заглушку, не удаляют карточку и не перезаписывают localStorage. Не выполнять массовое обогащение старых записей, миграцию их источников или поиск постера по похожему названию.
- Для карточек вне экрана использовать loading="lazy" и decoding="async"; выбранное превью загружать сразу после выбора. Указывать размеры или резервировать пропорции до загрузки. Установить referrerpolicy="no-referrer". Не запрашивать изображения сервером и не требовать image-CORS для чтения пикселей: здесь используется обычный img без canvas.
- В предпросмотре дать изображению alt с названием произведения, например «Постер: Матрица». В карточке, где рядом есть заголовок, допускается декоративный img с alt="" по существующей структуре. Текст «Нет постера» доступен скринридеру; декоративный 🎬 скрыт от него. Не добавлять изображению ненужный фокус и не перекрывать им элементы формы.
- На 375 px превью и поля располагаются с переносом или в один столбец; ширина изображения ограничена контейнером. Постер не растягивает страницу, не сжимает поля/кнопки ниже 44 px и не мешает вертикальной прокрутке. В карточках длинное название, две плашки рейтинга и действия помещаются без горизонтальной прокрутки. Сохранить бордово-золотой стиль, видимый фокус и рабочие кнопки «Смотреть»/избранного.

## Примеры
- В выбранном ответе Unofficial есть posterUrlPreview и posterUrl: превью берётся из posterUrlPreview. После выбора «Матрицы» изображение появляется рядом с данными; после добавления, F5 и перехода в «Избранное» используется тот же сохранённый posterUrl.
- В ответе ПоискКино poster.previewUrl пустой, poster.url содержит допустимый HTTPS-адрес: используется poster.url. Если вместо URL пришло null или javascript:alert(1), показывается «Нет постера», запись можно сохранить.
- Выбрать сериал, затем одноимённый фильм другого года: форма и новая карточка получают постер последнего выбранного ID, а не первого совпадения по названию.
- Началась загрузка картинки A, пользователь выбрал B. Поздний load или error для A не меняет предпросмотр B. Если B не загрузился, его область остаётся 2:3 с заглушкой.
- У нового результата нет постера: в форме и сохранённой карточке заглушка, posterUrl=null. Поля и кнопка добавления работают как раньше. Старая «Матрица» без поля posterUrl продолжает показывать ранее предоставленный matrix.jpeg и не изменяется в хранилище.
- Картинка сохранённого фильма временно недоступна или возвращает 404: показана заглушка, название, рейтинги и действия доступны. Ошибка не удаляет URL из записи и не запускает бесконечные повторы.
- После выбора изменить название и добавить другую запись по действующим правилам: постер прежнего фильма не переносится. При отказе сохранения черновик и предпросмотр остаются.
- На экране 375 px вертикальный постер не выходит за границы формы, подписи переносятся, а кнопки остаются высотой не меньше 44 px.

## Ограничения
- Реализация разрешена отдельным сообщением пользователя «делай». Обновить код, эту спецификацию и README.md; AGENTS.md, остальные спецификации, ключи и конфигурацию не менять. Существующий пользовательский каталог не мигрировать и не заменять ради проверки.
- При будущей реализации запрос пользователя разрешает внешнюю загрузку изображений именно по ссылкам из уже используемого API как исключение из общего запрета внешних ресурсов AGENTS.md. Сам поиск, ключ и способ подключения API остаются прежними. Новые npm-пакеты, библиотеки, endpoint, API-запросы, Google Images, Wikidata/Commons, парсинг сайтов и генерацию изображений не подключать.
- Разрешается только дополнить существующий результат новыми необязательными полями постера в адаптере/ответе сервера и состоянии выбора. Не менять получение и формат остальных данных. Наличие URL у каждого произведения не гарантируется; отсутствие постера — штатный случай.
- Не добавлять ручную загрузку файлов, редактирование URL пользователем, выбор из галереи, фоновое обновление старых карточек или скачивание всех постеров на сервер. Локальные предоставленные изображения не менять и не удалять.
- Постер необязателен и не подтверждает корректность рейтинга или других данных. Его отсутствие не добавляет новых причин блокировать сохранение. Существующие ограничения добавления из других уже реализованных функций продолжают действовать.
- Не обещать работу внешней картинки без сети или при запрете загрузки браузером/сервером изображения. В таком случае работает локальная заглушка. Не передавать изображениям ключ, заметки, личные оценки или содержимое каталога.

## Готово, когда
- На этапе спецификации создан только этот файл с разделами «Для кого и зачем», «Что должно быть», «Примеры», «Ограничения», «Готово, когда»; код и остальные файлы не изменены.
- После реализации подтверждено, что поисковые запросы и подключение ключа не изменились. Проверены оба набора полей постера, приоритет preview, переход к полному URL при пустом/неверном preview и отсутствие дополнительных запросов к API. Общий адаптер одинаково работает для file:// и HTTP(S).
- Проверены явный выбор, отсутствие постера, смена фильма и названия, сброс, поздние load/error и отсутствие переноса изображения от другого ID. Превью появляется только после выбора; сохранение выполняется только кнопкой добавления.
- Проверены загрузка и error, 404, отсутствие интернета, повреждённый URL и запрещённые схемы. Вместо сломанной картинки показана стабильная заглушка 2:3; нет циклической загрузки и изменений сохранённых данных из обработчика ошибки.
- Карточка хранит URL либо null и восстанавливает постер после F5/Command+R, в избранном, «Лучшем», после удаления/отмены. Старые записи без поля posterUrl и четыре локальных постера продолжают работать без миграции. Отказ localStorage сохраняет черновик.
- В браузере проверены форма и карточки с постером и заглушкой на 375 px, пропорции, рамка, длинные названия, alt, клавиатура, касания и кнопки от 44 px либо явно перечислены непроверенные режимы. Реальные изображения проверяются отдельно от фиксированных тестовых ответов; успех изолированных тестов не выдаётся за проверку доступности всех постеров.
- Выполнены применимые регрессии AGENTS.md: поиск/фильтры/счётчик, избранное после обновления, добавление и сохранность существующих данных. Источники, названия, год, рейтинги, длительность, личные оценки, заметки, статусы, даты и «Смотреть» не повреждены.
- После будущей реализации README.md дополнен возможностью, источником постера, правилами заглушки/старых записей и шагами проверки; после тестов создан Git-коммит. Итоговый отчёт перечисляет изменённые файлы, результаты и ограничения. Фактические результаты и непроверенные режимы явно указать в отчёте.
