# Автозаполнение названия и рейтингов Кинопоиска и IMDb

## Для кого и зачем
Для пользователя «Кадра», который вводит название фильма, выбирает нужное произведение по названию и году и получает заполненные поля «Рейтинг Кинопоиск» и «Рейтинг IMDb» без ручного переноса оценок.

## Что должно быть
- Использовать существующее верхнее поле «Название» формы добавления и существующие поля рейтингов, не создавать второй параллельный поиск. Нижний «Поиск по названию» над коллекцией продолжает фильтровать только localStorage.
- После паузы 400 мс с последнего завершённого ввода отправлять поисковый GET для строки длиной 3–160 символов без крайних пробелов. Пустой, короткий и незавершённый ввод IME не отправлять. Параметры формировать через URLSearchParams, не склеивать исходный текст с URL вручную.
- На опубликованном сайте сохранить автоматическое подключение ключа через /api/movie-search?query=НАЗВАНИЕ и серверное окружение. При открытии index.html через file:// автоматически загружать отдельный локальный local-api-config.js с provider/apiKey и выполнять прямой GET выбранному провайдеру с X-API-KEY. Этот файл исключён из Git, загружается только через file:// и не используется опубликованным сайтом. Общие адаптеры двух провайдеров находятся в movie-api.js. Посетитель не вводит токен в форму. Реальное значение не включать в спецификацию, URL, ответы, сообщения об ошибках и коммиты.
- Провайдера задаёт владелец в серверном окружении: MOVIE_API_PROVIDER со значением poiskkino или kinopoisk-unofficial. Если параметр отсутствует, сохраняется текущий poiskkino. Для ПоискКино использовать POISKKINO_API_KEY, для Unofficial — KINOPOISK_UNOFFICIAL_API_KEY. Не определять происхождение ключа по его внешнему виду, не переключать сервис автоматически после ошибки и не отправлять ключ другому провайдеру. Ранее проверенный в проекте ключ относится к ПоискКино; доступ к Unofficial этим ключом не подтверждён.
- Использовать один из двух адаптеров по настройке сервера:

| Провайдер | Поисковый GET | Массив результатов | Идентификатор | Название | КП | IMDb | Год |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Kinopoisk API Unofficial | https://kinopoiskapiunofficial.tech/api/v2.2/films?keyword=НАЗВАНИЕ&page=1 | data.items | item.kinopoiskId | item.nameRu, иначе item.nameOriginal | item.ratingKinopoisk | item.ratingImdb | item.year |
| ПоискКино | https://api.poiskkino.dev/v1.5/movie/search?query=НАЗВАНИЕ&page=1&limit=10 | data.docs | item.id | item.name, иначе item.alternativeName | item.rating.kp | item.rating.imdb | item.year |

- Корневые https://kinopoiskapiunofficial.tech и https://poiskkino.dev — адреса сайтов; для JSON нужны пути из таблицы. Не использовать старый поиск /api/v2.1/films/search-by-keyword с другой структурой ответа вместо items. Источники контракта: [OpenAPI Kinopoisk Unofficial](https://kinopoiskapiunofficial.tech/documentation/api/openapi.json) и [документация ПоискКино](https://poiskkino.dev/documentation). Оба сервиса сторонние; не представлять их как официальный API Кинопоиска или IMDb.
- Приводить ответы адаптеров к единой внутренней модели: название, год, идентификатор провайдера, kpRating и imdbRating. ID должен быть положительным безопасным целым числом; название — непустой строкой до 160 символов после удаления крайних пробелов. Неподходящие элементы пропускать, повторные ID внутри одного провайдера не показывать.
- Русское название имеет приоритет: nameRu у Unofficial, name у ПоискКино. Именно его подставлять вместо поискового текста, сохраняя внутреннюю пунктуацию и регистр ответа. Если русского названия нет, использовать указанное в таблице оригинальное название и пометку «Оригинальное название». Если нет обоих — результат пропускать. Не переводить название автоматически и не выдавать оригинальное за русское.
- Год брать только из допустимого четырёхзначного целого year. При отсутствии/недопустимости в варианте показывать «Год не указан», поле года оставлять пустым для ручного ввода. Не подставлять текущий год за неизвестный год выпуска.
- Под полем показывать до пяти подходящих уникальных вариантов в порядке ответа, с названием и годом для различения одноимённых фильмов. Существующие категории и компактные плашки КП/IMDb в подсказках можно сохранить. Первый результат автоматически не выбирать. Выбор доступен кликом, касанием и стрелками с Enter; фокус остаётся в поле.
- Если используется отдельная кнопка «Найти», она имеет type="button" и запускает тот же поиск сразу, без ожидания 400 мс и без отправки формы добавления. При неоднозначных результатах она открывает список для явного выбора, а не сохраняет первый фильм. Существующая кнопка «Смотреть» сохраняет прежнее назначение и не становится кнопкой поиска. Наличие «Найти» не обязательно для сценария с автоподсказками.
- При выборе заменить значение «Название» названием выбранного произведения, заполнить год и одновременно оба поля: «Рейтинг Кинопоиск» и «Рейтинг IMDb». Поля рейтингов — readonly, доступны для фокуса и копирования. Поля общего ручного рейтинга нет. Выбор не меняет статус просмотра, личную оценку, дату и заметку и не добавляет карточку автоматически.
- Каждый рейтинг проверять отдельно: конечное числовое значение больше 0 и не больше 10 форматировать через toFixed(1), например 8 → «8.0», 8.74 → «8.7». Для 0, null, отсутствующего поля, строки и недопустимого числа показывать «—»; в readonly-поле это может быть пустое значение с placeholder="—" и доступным пояснением «Нет оценки». Не подменять отсутствующий IMDb значением КП, личной оценкой или 0.0.
- При выборе второго фильма заменять оба рейтинга целиком. Если у него нет одного или обоих значений, соответствующие поля становятся пустыми с тире, а не сохраняют оценки предыдущего фильма. При изменении названия после выбора снимать привязку и очищать оба рейтинга; очищать только нетронутые импортированные метаданные, сохраняя ручные исправления года и других полей. После сброса и успешного добавления форма не содержит прежнего выбора.
- Сохранять карточку только кнопкой «Добавить в каталог» после обычной проверки обязательных полей. В localStorage сохранять kpRating и imdbRating как отдельные числа либо null; тире хранить не нужно. Сохранять также ratingProvider и ID источника: poiskkinoId для ПоискКино или kinopoiskId для Unofficial, отдельно от внутреннего ID карточки. Отсутствие рейтингов не блокирует добавление.
- В карточке показывать обе подписанные оценки «КП: 8.7» и «IMDb: 8.8» либо тире, а также источник данных. Плашки должны соответствовать той же записи после обновления страницы, в каталоге, избранном и «Лучшем». Внешние ссылки строить только из разрешённого домена и проверенного ID либо использовать фиксированную ссылку провайдера; произвольный URL из ответа не вставлять.
- Старые записи не переписывать автоматически: прежние источники, catalogRating, ID, постеры, статусы, оценки, заметки и даты сохраняются. Старый общий рейтинг не превращать в КП/IMDb. «Ваша оценка», сортировка «Лучшего» и статистика просмотренных категорий остаются независимыми от внешних оценок. Категория и длительность продолжают обрабатываться по существующим правилам; новая интеграция не выдумывает отсутствующие сведения и не переносит нетронутые импортированные поля другого фильма.
- Показывать состояния «Ищем…», «Выберите произведение из списка», «Ничего не найдено. Заполните форму вручную» и «Поиск недоступен. Заполните форму вручную». При ограничении запросов — «Лимит поиска исчерпан. Попробуйте позже». Не терять черновик при ошибках сети, HTTP, JSON, неверном массиве ответа, отказе авторизации или localStorage.
- При новом вводе, очистке, выборе, Escape, Tab, уходе фокуса и сбросе отменять актуальный запрос и игнорировать запоздалые ответы. Таймаут браузера — 8 секунд, провайдера — 6 секунд. После 429 учитывать допустимый Retry-After либо 10 секунд; автоматических повторов нет. Ответ 402 Unofficial трактовать как исчерпанную квоту, не как требование оплаты посетителем. Ошибки 401/403/503 не должны открывать форму ввода ключа посетителю.
- Сохранить серверные ограничения существующего маршрута: только GET, проверка query и источника браузерного запроса, фиксированные адреса провайдеров, отсутствие передачи клиентских cookies/заголовков провайдеру, безопасные сообщения без исходных тел ошибок. Кеш браузера — до 20 запросов на 5 минут; сервера — до 100 на 5 минут в памяти экземпляра, с разделением по провайдеру. Не сохранять историю поисков в localStorage. Ограничивать некешированные обращения до 30 в минуту на IP в пределах экземпляра, без обещания глобального межсерверного лимита.
- Использовать доступную комбинацию combobox/listbox, aria-expanded, aria-activedescendant, aria-selected и сообщения aria-live. Enter выбирает вариант без отправки формы, Escape/Tab закрывают список. Данные API выводить текстом. Сохранить бордово-золотое оформление, видимый фокус, поля и кнопки от 44 × 44 px и ширину 375 px без горизонтальной прокрутки; длинные названия переносятся.

## Примеры
- Фиксированный ответ Unofficial: nameRu=«Матрица», nameOriginal=«The Matrix», year=1999, ratingKinopoisk=8.7, ratingImdb=8.8. Пользователь вводит «матрица», через 400 мс выбирает «Матрица · 1999». В форме название становится «Матрица», КП — «8.7», IMDb — «8.8». После сохранения и F5 обе оценки остаются в карточке. Числа в примерах тестовые, а не утверждение о текущих рейтингах фильма.
- Ответ ПоискКино с name=«Начало», year=2010 и rating={kp:8, imdb:8.74} даёт название «Начало», поля «8.0» и «8.7». Поля ratingKinopoisk/ratingImdb у этого провайдера не используются.
- У первого результата обе оценки известны; у второго КП=0, IMDb=null. После выбора второго оба поля показывают «—», при сохранении оба значения null. Рейтинги первого не переносятся.
- nameRu пустое, nameOriginal=«Example Film»: список помечает оригинальное название; при выборе подставляется «Example Film», без выдуманного русского перевода. Если нет года, пользователь заполняет его сам.
- Два одноимённых фильма разных лет остаются отдельными вариантами. Ввод сам по себе, поиск и выбор не сохраняют ни один из них; пользователь нажимает «Добавить в каталог» для нужного.
- Пользователь исправил год, затем изменил название: исправленный год остаётся, прежний источник и оба рейтинга очищаются. Поздний ответ по предыдущему запросу ничего не подставляет.
- Ключ ПоискКино не принимается Unofficial: сайт не пробует автоматически другой домен, не показывает токен и оставляет ручное добавление доступным.
- Открыть index.html двойным щелчком при настроенном local-api-config.js: через 400 мс появляются реальные результаты API, выбор заполняет название и оба рейтинга. Если конфигурация отсутствует или недопустима, показать «Локальный ключ поиска не настроен. Заполните форму вручную» без запроса и без потери каталога.

## Ограничения
- Реализация разрешена отдельным сообщением пользователя «делай». Обновить код, эту спецификацию и README.md. AGENTS.md и остальные спецификации не менять; реальные ключи не коммитить. Номер и имя файла явно заданы пользователем; существующие спецификации с номером 009 не заменять.
- При будущей реализации эта спецификация уточняет сценарий названия и двух рейтингов поверх specs/009-poiskkino-ratings.md, сохраняя автоматическое серверное подключение ключа. Не возвращать прежний поиск Wikidata, поле ручного общего рейтинга или настройку токена для каждого посетителя.
- Только HTML, CSS и нативный JavaScript в браузере и серверной функции, без npm, сторонних библиотек и сторонних визуальных ресурсов. Автозаполнению нужен доступный серверный маршрут и настроенный токен выбранного провайдера. Не оформлять подписки, не обходить квоты и не предполагать совместимость ключей двух сервисов.
- Настройки Vercel применяются после нового развёртывания. Создание спецификации, наличие ключа в AGENTS.md и успешный отдельный запрос не означают, что окружение опубликованного сайта уже настроено. Не коммитить пользовательскую правку AGENTS.md, содержащую ключ.
- Через file:// поиск разрешён напрямую при локальной конфигурации и разрешённом CORS провайдера. Ключ виден владельцу локального браузера, но не публикуется в Git. Поставлять только local-api-config.example.js с заглушкой. Через HTTP(S) используется серверный маршрут; GitHub Pages и обычный статический сервер его не исполняют. Не отключать защиту браузера и не использовать no-cors.
- Не добавлять автоматическое сохранение первого результата, фоновое обновление старых рейтингов, массовое обогащение каталога, новые постеры, актёров, рекомендации или дополнительные запросы за подробностями. Если поисковый ответ не содержит оценку, отображать тире.
- Внешние оценки меняются со временем и могут отсутствовать. Сохраняется снимок на момент выбора; обновление рейтинга старой карточки в этой задаче не предусмотрено. Сохранения браузера не переносятся автоматически между file:// и доменами сайта.

## Готово, когда
- На этапе спецификации создан только этот файл; в нём есть «Для кого и зачем», «Что должно быть», «Примеры», «Ограничения» и «Готово, когда». Рабочий код, README.md, другие спецификации и настройки публикации не изменены.
- После реализации каждый адаптер отдельно проверен фиксированными ответами: точный endpoint, параметры, X-API-KEY на сервере, items/docs, ID, русское/оригинальное название, пустые и неверные данные, год, независимые рейтинги. Ключ не отправляется второму провайдеру и не появляется в общих исходниках или ответах сервера. HTTP(S)-страница не загружает локальный файл с ключом.
- Подтверждены задержка 400 мс, минимальная длина, IME, максимум пять уникальных вариантов, различение одноимённых фильмов, доступный явный выбор, отмена и игнорирование старых ответов. При наличии «Найти» она не подменяет «Смотреть», не отправляет форму добавления и не выбирает первый из нескольких фильмов.
- Выбор одновременно заполняет название, год и два readonly-поля. Проверены 8 → 8.0, округление, 0/null/отсутствие, неверные типы, смена результата, очистка и сброс; оценки предыдущего фильма не остаются. Личная оценка, заметка и статус сохраняются.
- Только явное сохранение создаёт карточку с двумя отдельными рейтингами, источником и ID. Проверены F5/Command+R, избранное, «Лучшее», удаление/отмена, отказ localStorage и старые записи без новых полей. Старые общие рейтинги и прочие пользовательские данные не мигрируют автоматически.
- Проверены сеть, 401/402/403/429/503, таймаут, повреждённый JSON, отсутствие массива, кеш и серверные ограничения. При ошибках и без локального ключа работает ручное добавление; данные формы не теряются.
- Отдельно проверены реальный запрос только к настроенному провайдеру и опубликованная функция с правильным окружением. Поддержка второго адаптера проверяется без реального запроса, если подходящего ключа нет; это явно отмечено. Изолированные тесты не выдаются за подтверждение опубликованной интеграции.
- Выполнены визуальная проверка ширины 375 px, областей нажатия от 44 px, клавиатуры, касаний и доступных сообщений либо перечислены непроверенные режимы. Пройдены применимые регрессии из AGENTS.md: поиск/фильтры и счётчик, избранное после обновления, сохранность каталога и статистики.
- После будущей реализации обновлён README.md: автозаполнение, провайдер, серверное окружение, два поля и шаги проверки. После тестов создан Git-коммит по AGENTS.md; отчёт перечисляет изменённые файлы, проверки и ограничения. Публикацию и настройку окружения подтверждать фактическим результатом, а непроверенные режимы перечислять явно.
