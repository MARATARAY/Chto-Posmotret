# Онлайн-поиск фильмов, сериалов и мультфильмов через Wikidata

## Для кого и зачем
Для пользователя «Кадра», который вводит русское название произведения, выбирает подходящий результат из интернета и получает заполненную форму добавления без API-ключа.

## Что должно быть
- Онлайн-поиск работает в поле «Название» формы добавления. Нижнее поле «Поиск по названию» фильтрует только сохранённый каталог и не отправляет запросов.
- Использовать встроенный fetch и публичный Action API Wikidata: https://www.wikidata.org/w/api.php с параметрами action=wbsearchentities, search=название, language=ru, uselang=ru, type=item, format=json, origin=* и limit=20. Адрес https://wikidata.org — адрес сайта, а для JSON нужен путь /w/api.php. Документация: https://www.mediawiki.org/wiki/Wikibase/API и https://www.wikidata.org/wiki/Wikidata:Data_access/ru.
- После ввода 3–160 символов без крайних пробелов и паузы 500 мс выполнять HTTPS GET. Пустые, короткие запросы и незавершённый ввод IME не отправлять. Авторизация, ключи, npm, библиотеки и серверный обработчик не нужны.
- Обрабатывать только массив data.search. Элемент должен иметь ID вида Q123, непустой label не длиннее 160 символов и строковый description. Название брать из label, описание анализировать без учёта регистра.
- Сначала проверять слова «мультфильм», «анимационный», «мультсериал», «аниме» — категория «Мультфильм». Затем «телесериал», «сериал», «мини-сериал» — «Сериал». Затем «фильм», «кинофильм», «комедия», «триллер», «боевик», «фантастика», «драма» — «Фильм». При совпадениях нескольких групп действует этот порядок. Не вводить дополнительные категории.
- Не показывать неподходящие сущности: без ключевых слов, без описания, книги, игры и людей. Дополнительно отбрасывать описания с явными словами «роман», «книга», «видеоигра», «игра», «актёр», «актриса», «режиссёр», «писатель» как отдельными словами, учитывая варианты е/ё. Не путать их с «романтическая комедия» или «фильм режиссёра». Фильтрация по описанию — эвристика; дополнительные запросы к свойствам сущности не выполнять.
- Год извлекать первым совпадением регулярного выражения /\b(19|20)\d{2}\b/ из description. Если совпадения нет, подставлять текущий год по локальному календарю браузера. В списке и сообщении после выбора обозначать, когда использован текущий год.
- Поиск Wikidata не предоставляет зрительский рейтинг и длительность. Подставлять рейтинг 0.0, длительность 120 минут для «Фильма» и «Мультфильма», 1 сезон для «Сериала». Это значения по умолчанию, а не сведения Wikidata; явно пояснять это в форме. Все поля можно поправить перед сохранением.
- Показывать максимум пять подходящих уникальных сущностей в порядке ответа; дубликаты определять по ID. Вариант содержит название, год, рейтинг 0.0 с пометкой «по умолчанию» и категорию. Если среди первых результатов есть книги и люди, пропускать их и продолжать до пяти подходящих вариантов или конца ответа. Первый результат автоматически не выбирать.
- Клик или Enter на активном варианте заполняет название, категорию, год, рейтинг и длительность. Обновлять единицу длительности и очищать устаревшие метаданные предыдущего выбора. Сам выбор не сохраняет карточку. Статус просмотра, личную оценку и впечатления не менять; описание не переносить в личные заметки.
- После выбора показать ссылку «Данные Wikidata» на https://www.wikidata.org/wiki/Q123 и сообщение: рейтинг и длительность заданы по умолчанию, год текущий при отсутствии года в описании, поля нужно проверить. Не подписывать 0.0 как «Рейтинг Wikidata».
- Изменение названия после выбора снимает привязку к сущности и очищает только нетронутые импортированные поля. Ручные исправления сохранять. Повторный явный выбор заменяет метаданные новым результатом.
- Сохранять запись по кнопке «Добавить в каталог» после обычной проверки формы. В localStorage сохранять необязательный wikidataId отдельно от внутреннего ID. Показывать источник в карточке после перезагрузки. Старые записи, включая источники и рейтинги TVmaze, сохраняются без миграции и подмены.
- Пока идёт запрос, показывать «Ищем…». Если подходящих результатов нет — «Ничего не найдено. Попробуйте другое название или заполните форму вручную». При ошибке сети, JSON, HTTP, поле error в ответе API или таймауте 8 секунд — «Поиск недоступен. Заполните форму вручную». При 429 — сообщение о лимите и пауза согласно доступному Retry-After либо 10 секунд. Автоматических повторов нет.
- Отменять запрос и игнорировать запоздалые ответы при новом вводе, очистке, выборе, Escape, Tab, уходе фокуса и сбросе формы после добавления. Не терять введённые данные при ошибках API или localStorage.
- Кешировать до 20 запросов в памяти на 5 минут, не сохранять историю поиска в localStorage. Работать через file:// и на опубликованном сайте; при запрете запроса браузером оставлять ручной режим без отключения защиты.
- Подсказки доступны мышью, касанием и клавиатурой: стрелки меняют активный вариант, Enter выбирает без отправки формы, Escape и Tab закрывают список. Использовать combobox/listbox, состояния загрузки, выбора и раскрытия; фокус остаётся в поле при обновлении и выборе. Сообщения доступны скринридеру.
- Сохранить оформление, контур фокуса, области нажатия от 44 × 44 px и отсутствие горизонтальной прокрутки на 375 px. Названия и описания из API выводить как текст; внешние ссылки строить только из проверенного Q-ID, игнорируя URL ответа.

## Примеры
- Ввести «Интерстеллар»: результат с описанием «фильм Кристофера Нолана 2014 года» получает категорию «Фильм», год 2014, рейтинг 0.0 и длительность 120 мин. Выбор заполняет форму; после нажатия «Добавить в каталог» и обновления карточка и ссылка на Wikidata остаются.
- Описание «анимационный телесериал 2012 года» получает категорию «Мультфильм» по приоритету анимации и длительность 120 мин. Пользователь может изменить категорию и длительность вручную.
- Описание «мини-сериал 2010 года» даёт «Сериал», год 2010 и 1 сезон.
- Описание «комедия» без года даёт категорию «Фильм», текущий год (например, 2026), рейтинг 0.0 и 120 мин. Подстановка текущего года явно обозначена.
- Роман, компьютерная игра, актёр и результат без description не появляются в списке. Из двух одноимённых экранизаций можно выбрать нужную по году.
- Быстро заменить название: старый ответ не открывает список. При недоступном интернете можно заполнить и сохранить карточку вручную.
- Исправить импортированный год и рейтинг, затем изменить название: ручные значения остаются, прежняя ссылка Wikidata снимается, нетронутые поля очищаются.

## Ограничения
- Реализация разрешена текущим запросом пользователя; обновить этот файл, код и README.md. Имя спецификации явно задано независимо от существующей нумерации.
- Эта версия заменяет сетевой поиск TVmaze и прежний ПоискКино. Не отправлять запросы к старым провайдерам и не требовать ключей. Поддержку отображения уже сохранённых карточек TVmaze оставить.
- Разрешены только HTTPS GET к открытому API Wikidata с origin=*. Наружу передаётся поисковое название, не каталог, история, заметки или оценки. Не подключать библиотеки, сервер, платные API, постеры, SPARQL, дополнительные запросы за рейтингом и длительностью.
- Назначение категории и год берутся из свободного описания, поэтому не гарантировать полноту каталога или точную классификацию. Предоставить ручное исправление всех полей; не выдавать значения по умолчанию за фактический рейтинг и длительность.
- Существующие ID, статусы, личные оценки, избранное, даты и заметки не менять. Сохранить фильтрацию, счётчики, добавление, ошибки сохранения, удаление с отменой, «Лучшее» и итоги месяца.

## Готово, когда
- Запрос содержит правильный путь API, action=wbsearchentities, русский язык и origin=*, отправляется после 500 мс без ключа. В браузере нет запросов к TVmaze и ПоискКино.
- Проверены все группы слов и их приоритет, нерелевантные сущности, пустые/неверные поля, дубликаты, безопасный текст, максимум пять вариантов, год по регулярному выражению и текущий год при отсутствии совпадения.
- Выбор заполняет все пять полей, рейтинг всегда 0.0, длительность 120 мин либо 1 сезон по категории; значения по умолчанию обозначены и редактируются. Личные поля не меняются, карточка сохраняется только по кнопке.
- После F5 и Command+R сохранены wikidataId и ссылка; источник не приписывается ручному рейтингу. Старые карточки и источники TVmaze продолжают отображаться.
- Пройдены проверки задержки, IME, кеша, устаревших ответов, Escape/Tab/blur/reset, HTTP-ошибок, ошибок API, таймаута, отсутствия сети, 429 и отказа localStorage. Ручной режим работает без потери данных.
- Изолированные тесты используют фиксированные ответы; отдельно проверены реальные русские запросы, опубликованный сайт, file://, мобильная ширина 375 px, клавиатура, касания и скринридер либо явно перечислены оставшиеся непроверенными режимы.
- README.md описывает Wikidata, начальные значения и шаги ручной проверки. Выполнены применимые регрессионные проверки из AGENTS.md, после тестов создан Git-коммит; отчёт перечисляет изменения, результаты и ограничения проверки.
